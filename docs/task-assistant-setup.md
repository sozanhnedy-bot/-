# إعداد تطبيق World News Android

## إصدار Android

الإصدار الجاري تطويره هو `1.4.0` (`versionCode 6`) ومعرّف التطبيق المثبت هو `com.worldnews.newsapp` لمطابقة تطبيق Firebase المسجل. namespace الداخلي لكود Android ما زال `com.threadsdocumentarynews.app` ولا يغيّر معرّف التطبيق المثبت. سير GitHub Actions يبني APK تجريبيًا باسم `World-News-v1.4.0-debug` بعد نجاح اختبارات Android. تغيير applicationId يجعل هذا التطبيق يُعامل كتطبيق منفصل عن الإصدارات ذات المعرّف السابق عند التثبيت والتحديث. هذا APK تجريبي وليس نسخة متجر.

يتحقق سير البناء من بصمة مكتبة sherpa-onnx الرسمية، ويشغّل اختبارات JVM، ويبني التطبيق ويتحقق من توقيعه. لا تُحفظ مكتبات النماذج الكبيرة أو مفاتيح Gemini في Git.

## تحليل الأخبار باستخدام Gemini

من البوابة الرئيسية افتح «تحليل Gemini». يجلب التطبيق أحدث 40 عنوانًا من ملف الأخبار العام على GitHub Pages، مع المصدر والقسم والتاريخ، ويرسل هذه البيانات فقط مع مجال التركيز الاختياري إلى Gemini 3.5 Flash-Lite عبر Firebase AI Logic. يحاول النموذج جمع العناوين المتشابهة معنويًا، وتلخيص سبب بروز الموضوع في العينة، واقتراح زاوية صحفية وأسئلة تحتاج إلى تحقق. لا يرسل التطبيق ملخصات الأخبار أو روابطها، ولا يملك هذا التحليل بيانات Google Trends أو X؛ لذلك لا يثبت أن موضوعًا ترند رسمي ولا يتحقق من صحة الخبر.

يطلب التطبيق موافقة قبل كل إرسال. في الطبقة المجانية قد تستخدم Google الطلبات لتحسين منتجاتها. لا يحتاج نموذج `gemini-3.5-flash-lite` إلى ربط Cloud Billing بحسب فهرس Firebase AI Logic الحالي، لكن تبقى حدود الاستخدام المجاني وحصة المشروع سارية. لم يُفعّل أي استخدام مدفوع.

### إعداد مشروع Firebase مرة واحدة

التكامل لا يضع مفتاح Gemini في APK. يستخدم Firebase AI Logic SDK الرسمي وApp Check. قبل استخدام التحليل:

1. سجّل تطبيق Android بالمعرّف `com.worldnews.newsapp` داخل مشروع Firebase الحالي.
2. من Firebase AI Logic اختر Gemini Developer API، ثم فعّل الوصول إلى نموذج Gemini المجاني. لا تربط Cloud Billing إذا كنت تريد البقاء على الطبقة المجانية.
3. فعّل Firebase App Check لتطبيق Android. عند تجربة Debug سيظهر رمز Debug App Check في Logcat؛ أضفه إلى قائمة Debug tokens في Firebase Console. لا تضع هذا الرمز في GitHub أو APK. إصدار الإنتاج يستخدم Play Integrity ويحتاج إعداد بصمة توقيع التطبيق في Firebase.
4. استخرج `current_key` من `client[].api_key[]`، و`mobilesdk_app_id` من إعداد العميل، و`project_id` من `project_info` في إعداد تطبيق Firebase. محليًا أضفها إلى `android-app/local.properties` (وهو مستثنى من Git):

   ```properties
   firebase.apiKey=YOUR_FIREBASE_ANDROID_API_KEY
   firebase.appId=YOUR_FIREBASE_MOBILE_SDK_APP_ID
   firebase.projectId=YOUR_FIREBASE_PROJECT_ID
   ```

   هذه بيانات إعداد Firebase للعميل وليست مفتاح Gemini السري. يعتمد الوصول إلى AI على إعداد Firebase وApp Check، ولا يُحفظ مفتاح Gemini في التطبيق.
5. لبناء APK عبر Actions، أضف القيم نفسها في إعدادات المستودع كأسرار باسم `FIREBASE_API_KEY` و`FIREBASE_APP_ID` و`FIREBASE_PROJECT_ID`. دون هذه الإعدادات يظل البناء ناجحًا، لكن شاشة التحليل تعرض أن Firebase غير مهيأ ولا ترسل طلبًا.
6. لنسخة Debug الاختبارية فقط، أضف `FIREBASE_DEBUG_TOKEN` كسر مستودع اختياري. يمرره البناء إلى `firebase_app_check_debug_token` كي يستطيع Debug App Check استخدام التوكن المسجل في Firebase Console. لا تستخدمه في إصدار إنتاجي؛ أي شخص يحصل على APK الاختباري يمكنه استخراج التوكن منه. إذا لم تضف السر، يبقى التطبيق قادرًا على توليد توكن Debug وإظهاره في Logcat.

إذا رفض Firebase App Check الطلب، راجع تفعيل Gemini Developer API وتسجيل Debug token. إذا انتهت الحصة المجانية، انتظر تجددها؛ لا تربط الفوترة من دون قرار واعٍ.

## مساعد كتابة الفيديو المحلي

من تبويب «المساعد» اكتب فكرة الفيديو، وأضف اختياريًا حقائق أو مقتطفات تريد أن يلتزم بها النموذج. اختر المنصة والمدة والنبرة، ثم نزّل نموذج Qwen المفتوح (~491 MB) من داخل التطبيق عند الرغبة في الكتابة دون اتصال. ينشئ النموذج عنوانًا وفكرة وتعليقًا صوتيًا وتقسيمًا لمشاهد. النموذج المحلي لا يتصل بالإنترنت للتحقق من الأخبار؛ راجع الأسماء والأرقام والحقائق بنفسك.

يمكن تنزيل صوت Nabra العربي المفتوح (~83 MB) لإنشاء معاينة WAV أو استخدام صوت Android المتاح على الجهاز، كما يتاح تصدير PDF وحفظ المشروع محليًا. إنشاء لقطات تصوير أو ملف MP4 نهائي غير مدعوم في هذا الإصدار.

توليد السكريبت والصوت المحلي لا يحتاج إلى مفتاح API أو رسوم استخدام. يلزم اتصال ومساحة للتنزيل الأولي فقط.

## حفظ المشروعات ومهام GitHub

يحفظ التطبيق آخر مشروع محليًا على الهاتف، ولا يرفع بياناته. من تبويب «المشاريع» افتح مهمة GitHub Actions لتعديل الموقع وسجّل الدخول بحساب يملك صلاحية التشغيل. لا تلصق PAT أو مفتاح API داخل التطبيق.

## نشر X وFacebook

تبويب «النشر» يجهز مسودة قابلة للتحرير والنسخ ولا ينشر تلقائيًا. أي نشر فعلي يحتاج إعداد حسابات المنصات وموافقة منفصلة على الصلاحيات والتكلفة.

## متطلبات التوافق

- Android 7.0 أو أحدث (API 24+)، وبنية `arm64-v8a`.
- الإنترنت مطلوب لتحليل Gemini وتنزيل النماذج.
- تحليل Gemini يحتاج Firebase project وتهيئة App Check؛ لا يحتاج Gemini API key داخل التطبيق.
- يظل مساعد الفيديو والصوت المحليان منفصلين عن خدمة Gemini ويعملان دون اتصال بعد تنزيل النموذجين.
